# V1 学习与开发说明：知识库问答系统

## 1. V1 要完成什么

V1 要完成一个最小知识库问答系统。

用户可以上传一段企业文档，比如制度、合同、FAQ 或项目记录。系统把文档切成小段保存起来。用户提问时，系统从这些小段里找出最相关的内容，并基于这些内容回答。

## 2. V1 的最小流程

```text
用户上传文档
  -> 后端读取文本
  -> 文档切块
  -> 保存 chunk
  -> 用户提问
  -> 检索相关 chunk
  -> 生成回答
  -> 返回答案和来源
```

## 3. 每一步在学什么

### 3.1 上传文档

学习重点：

- HTTP 文件上传
- FastAPI 接收文件
- 文档元数据保存

第一版只支持 `.txt` 和 `.md`。

### 3.2 文档切块

大模型不能每次都读取完整文档，所以要把长文档拆成多个 chunk。

第一版使用简单规则：

```text
每 600 个字符切一块，相邻块之间保留 100 个字符重叠。
```

重叠的原因是避免一句话刚好被切断，导致上下文丢失。

### 3.3 检索

真实 RAG 会使用 embedding 和向量数据库。

第一版为了好理解，先用关键词重叠：

```text
用户问题和 chunk 中出现的相同词越多，说明越相关。
```

后续会替换成：

```text
OpenAI embedding -> pgvector 相似度检索
```

### 3.4 回答生成

真实系统会把检索到的 chunk 发给大模型生成回答。

第一版先返回一个模板答案：

```text
根据已检索到的资料，相关内容如下...
```

这样你可以先看清楚数据流。后续再接入大模型。

### 3.5 来源引用

回答必须带来源。

来源至少包含：

- 文档名称
- chunk 编号
- chunk 内容片段

这是企业 AI 系统非常重要的能力，因为用户需要知道答案从哪里来。

## 4. 当前后端接口设计

### 健康检查

```http
GET /health
```

用途：确认服务是否启动。

### 上传文档

```http
POST /documents
```

请求：`multipart/form-data`

字段：

```text
file: txt 或 md 文件
```

返回：

```json
{
  "document_id": "xxx",
  "filename": "example.md",
  "chunk_count": 3
}
```

### 提问

```http
POST /chat
```

请求：

```json
{
  "question": "客户 A 的项目为什么延期？"
}
```

返回：

```json
{
  "answer": "根据已检索到的资料...",
  "sources": [
    {
      "document_id": "xxx",
      "filename": "example.md",
      "chunk_index": 0,
      "score": 3,
      "content": "..."
    }
  ]
}
```

## 5. 后续真实版替换点

| 当前简化实现 | 后续真实实现 |
| --- | --- |
| 内存保存 chunk | PostgreSQL 保存文档和 chunk |
| 关键词检索 | OpenAI embedding + pgvector |
| 模板回答 | 大模型生成回答 |
| 只支持 txt/md | 支持 PDF/DOCX/HTML |
| 无用户系统 | JWT 登录和权限控制 |

## 6. 初学者要先吃透的核心问题

你先不要急着背框架名。先回答清楚这些问题：

1. 为什么文档要切块？
2. 为什么回答要带来源？
3. 检索和生成分别在做什么？
4. 为什么第一版可以不用多 Agent？
5. 后续为什么要把关键词检索换成向量检索？

能回答这些问题，说明你已经理解 RAG 的底层流程了。
