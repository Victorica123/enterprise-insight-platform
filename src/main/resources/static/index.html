模式说明

面试时可以按这三句话解释取舍

普通上传 简单可靠，但应用服务器压力最大
Redis 分片 解决大文件中断、重试、合并一致性
对象存储 让文件流量绕开应用服务器
MQ 异步 高峰先接住请求，后台慢慢消费
ops

工程验证

把后端能力翻译成可以演示的业务现象

MQ 削峰 不是让单个任务更快，而是高峰时先接住请求，再排队处理，减少直接失败。
P3 任务补偿 处理进程异常中断时，定时器会把卡住的任务重新放回队列。
P4 对象存储 视频文件可从应用服务器磁盘迁到 MinIO/S3，降低服务器磁盘和播放流量压力。
失败重试 历史任务失败后可手动重试，适合临时网络、转写服务抖动等可恢复问题。
