# 产品知识

## 一句话定位

Enterprise Insight Platform 将客户访谈、需求评审、故障复盘等视频及配套业务文档，转化为可回放验证的需求证据、结构化洞察、可评审 PRD 和可追踪行动项。

它不是“视频站 + 聊天机器人”的拼接，也不是通用网盘。核心价值是缩短从非结构化沟通到可信业务决策的距离。

## 目标用户

- 产品经理：从多场访谈中提取需求、冲突、优先级和 PRD 草案。
- 研发与测试负责人：查看每条需求的原始证据、约束和验收口径。
- 项目或交付负责人：跟踪风险、待确认问题、负责人和截止时间。
- 企业管理员：管理租户、成员、数据边界和审计记录。

## 核心业务闭环

1. 用户上传会议视频并查看可靠的媒体处理进度。
2. Media Service 生成带时间段和说话人的转写片段。
3. 转写完成事件被 Agent Service 幂等接收，片段成为可检索证据。
4. 用户在统一工作台跨视频提问，答案引用可点击回放的时间段。
5. Agent 按意图、干系人、领域深挖、风险、收敛、PRD 六阶段产出需求分析。
6. 未收敛信息进入人工补充或确认；会话可等待并恢复。
7. PRD 发布进入人工审批：个人 Workspace 由 OWNER 二次明确确认，团队 Workspace 由不同成员四眼审批，结果保留审计链。
8. 发布事务固化不可变 PRD 版本，并生成仍需人工决定的知识候选与行动项草稿。
9. 行动项只能进入受控工单审批；坏案例进入评测和规则改进流程。

## 首条可交付纵向链路

首条纵向链路已经贯通：统一登录与租户边界 → 视频转写进入 Agent → 时间戳证据问答 → 六阶段等待/恢复 → 证据化 PRD → Workspace 策略审批与审计 → 不可变版本 → 知识候选人工决定 → 行动项工单审批。旧图谱、工单与明细审计也已完成 tenant/owner 迁移，不再以 JWT 模式 503 代替授权。

当前下一项产品决策是团队 Workspace 的邀请、角色和活跃 Workspace 切换语义；生产身份提供方、保留期限、企业共享粒度和外部模型数据策略仍需用户批准。

注册用户自动获得一个个人工作区并成为 owner；后续企业协作通过邀请加入其他工作区，而不是共享全局默认租户。

## 成功标准

- 同一身份可在一个前端完成上传、进度查看、提问和证据回放。
- 任一跨租户或跨 owner 访问被服务端拒绝，而不是只在 UI 隐藏。
- 转写完成重复通知不会产生重复片段或重复索引。
- 视频答案的关键结论包含 `asset_id`、开始/结束时间和可回放定位。
- 模型不可用时，媒体处理事实、已入库证据和审批状态仍可查询。
- PRD 中无法由证据支持的内容被标识为假设或待确认，而非伪装成事实。
- 个人发布需要两次显式操作；团队提交者不能批准自己的 PRD，跨租户审批表现为资源不存在。
- 发布成功必须同时生成可校验哈希的不可变 PRD 版本；知识与行动执行都保留独立人工门禁。
- 上述核心闭环可在本机完成验收，不依赖公网服务器、正式域名、云存储或外部模型账号。

## 当前非目标

- 取代专业视频剪辑、直播或内容分发平台。
- 允许 Agent 无审批地向外部系统执行高风险写操作。
- 在首个整合版本中同时支持任意身份供应商、任意消息队列和任意模型平台。
