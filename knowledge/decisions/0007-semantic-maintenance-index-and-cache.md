# ADR-0007：维护知识语义索引与计算缓存

- 状态：已接受
- 日期：2026-08-30

## 背景

项目知识库已经能按主题人工路由，但跨服务维护仍需要 Agent 读取较多文件。把完整文档或原始向量直接放入 `SKILL.md` 会增加稳定上下文、降低命中模型前缀缓存的机会，也会使 Skill 与知识源重复。业务 Agent 的客户证据索引又不能与工程维护文档混用。

## 决策

- 人工维护的 `knowledge/` 和契约继续是真实来源；生成向量只是可再生路由层。
- 新增独立的维护语义索引，只扫描仓库文档、ADR、契约和项目 Skill 参考，不读取客户数据库、媒体或 runtime 数据。
- 使用确定性的 192 维 hash n-gram + topic embedding，使索引无需外部模型即可在本地和 CI 重建。
- 维护向量归一化后量化为 signed int8 并以 Base64 持久化，查询时恢复近似浮点向量执行 cosine，避免把大段十进制浮点数组变成 Git 噪音。
- chunk 以内容 SHA-256 寻址；增量构建复用未变化向量。查询缓存 key 包含 corpus revision、query digest 和 Top-K；revision 同时绑定语料、索引版本、分块算法、向量算法和维度，任一变化都会自动失效。
- Skill 只加载稳定不变量，并先用索引检索 Top-K 文件与行号，再读取原文；不把大向量 JSON 注入模型上下文。
- 业务侧真实 embedding 增加有界、摘要 key 的进程内 LRU，复用重复文本向量；现有带 scope 与 content revision 的 chunk LRU 保持不变。
- 明确区分应用缓存和模型 attention KV cache。没有 provider/runtime 证据时，不宣称模型级 KV 命中。

## 结果

维护任务可以在较小上下文中命中相关事实，知识更新仍受漂移检查约束；向量重建和重复 query 的成本降低。代价是增加一个生成索引和缓存失效机制，且确定性 hash embedding 的语义能力弱于 BGE，因此它只用于工程文档路由，不能替代业务 RAG 的真实模型评测。
