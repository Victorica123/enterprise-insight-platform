# ADR-0019：检索排名、通道隔离与证据观测

- 状态：已接受
- 日期：2026-09-13
- 范围：补齐已批准 Nexus 对照方案中的检索机制；不改变服务、身份、模型、审批或数据库 schema。

## 背景

实际调用链存在四类问题：回答层覆盖 RRF/精排顺序，弱候选没有先做通道过滤，通道异常/卡住影响整个请求，以及精排返回长度/有限值没有校验。重试合并还可能丢失原始 query。仅测试检索器内部排序不能发现最终证据被改序的问题。

## 决策

1. `RetrievalHit.selection_rank` 保存最终名次，`score` 保存实际相关性。standard/agentic 的 Top-K 与预算尊重名次；keyword/embedding 单通道保留原标题先验。hybrid 的标题先验只用于融合前的关键词排序。分析快照继续冻结既有返回顺序、实际分数、query、revision 与 SHA-256。
2. 通道先过滤：keyword 至少达到本通道最高分的 0.35；语义和 hash 的 0–100 分最低值分别为 45、10。零分始终排除。相关性仍为接受信号的固定 0.5/0.5 加权，缺失/失败通道不重归一化，不因降级而提高置信度。
3. 真实语义向量走 RRF（K=60），平局看关键词覆盖分及加权相关性。64 维 hash n-gram 是词面近似，不作为独立语义投票：`keyword_then_hash` 保留已接受的关键词排名，再补 hash 独有候选。该分支在 trace 明确标识；不能混报为真实语义融合质量。
4. 多轮去重独立保留最佳最终名次、最高相关性和按首次出现顺序的 query 并集；同名次稳定保留首次出现顺序，不用原始分重新覆盖名次。
5. `retrieval_execution.py` 使用进程共享的 keyword、embedding、rerank 三个独立线程池，每个默认 4 个在途任务，信号量覆盖运行与待启动任务，不提供额外无界队列。分别返回 ok / error / timeout / saturated；一条通道失败仍可使用另一条合格证据。
6. 默认通道截止 2 秒、精排截止 3 秒，均从提交起计算。等待期间检查取消/租约 guard，worker 复制 ContextVar 并在执行前后检查；不吞掉 `ChatCancelled`。超时后只丢弃该结果，不能通过 `shutdown(wait=True)` 继续阻塞请求，也不为挂住的任务另建替代线程池。
7. 精排须返回与候选等长、可转 float、全为有限值的数组；推理异常、畸形输出、超时或饱和都保留精排前排序并记录原因。真实精排仍是可选能力，不改变现有部署模型。
8. `retrieval_*` trace 记录通道原始候选数、接受数、最终预算后保留的来源锚点数、阈值、实际耗时和降级策略。章节扩展的邻块不重复算成新来源锚点。日志复用现有 `TraceStep.detail`，无需扩张公共 schema。

## 代价与边界

- Python 无法终止已进入原生库的推理；超时任务保留其槽位直到退出，持续卡住的通道会快速拒绝新任务，恢复可能需要重启 Agent。线程总量有界，不代表推理能强制中断。
- 容量按每进程计算；默认最多 12 个通道任务同时在途。进程数、模型内存及 HTTP 线程池仍须共同量测。通道截止不替代数据库/HTTP/外部模型的其他超时。
- 过滤和降级排序是本项目的明确适配，不能机械把真实 embedding 阈值用于 hash，也不能借黄金集结果宣称真实模型质量提升。
- 保留已批准的“子块精排 → Top-K 锚点 → 同章节扩展 → 字符预算”顺序，视频不合并。没有新增整父块 rerank、表格或图谱通道。

## 验证

`tests/test_retrieval_pipeline.py` 覆盖真实 standard/agentic 回答选择、反向原始分/最终排名、分析快照、重试来源并集、弱命中过滤、hash 碰撞、预算后计数、双向通道故障、超时/满员/迟到结果/取消/上下文传播、畸形精排与 legacy adapter。Settings 的边界值在 `tests/test_settings.py` 验证。

V6 增补排序问题，并修正真实 Top-3 与 hybrid 决策门禁；原 `baseline_v6.json` 保留为历史记录，旧 recall3 曾覆盖最多四条，不能直接比较。完整数量、环境及部署证据见 [QUALITY.md](../QUALITY.md) 与 [参考站复核](../../docs/NEXUS_REFERENCE_AUDIT.md)。
